# batch（毎営業日の処理・通知）

PDCA仕組み化の毎営業日バッチを置くフォルダです（方針は `docs/共通引継ぎプロンプト_PDCA仕組み化.md` 6章）。
いまは **Teams 通知のテスト送信** だけがあります。

## Teams 通知のテスト（まず中島さんの個人チャットへ）

最終的には Teams のチャネルへ通知します。まず中島さんの個人チャットに届くことを試します。

### 1. Teams でワークフローを作る（中島さん・5分程度）
1. Teams の左の「…（その他のアプリ）」から **「ワークフロー（Workflows）」** を開く。
2. テンプレートから **「Webhook 要求を受信したらチャットに投稿する」**（英語表示なら *Send webhook alerts to a chat*）を選ぶ。
   - テンプレート名は表示言語や時期で少し違うことがあります。「Webhook」と「チャット」を含むものを選んでください。
3. 接続（Microsoft Teams）を確認して「次へ」。
4. 投稿先のチャットで、**自分（Flow bot とのチャット）** を選び、「ワークフローを作成」。
5. 表示された **URL をコピー**する（この URL はキーと同じ扱い。チャットやメールに貼らない）。

### 2. URL を保存する（中島さん）
- メモ帳などで、URL だけを1行書いたテキストファイルを作り、**中島さんだけが見られる Box のフォルダ**に保存する。
  - 例：`C:\Users\612316\Box\【個人】612316_中島　麻耶\keys\teams_webhook_test.txt`
  - アプリの運用フォルダ（`生成AI\KPI-PDCA`）や【外部】フォルダには置かない。
- 保存した場所を Claude に伝える（URL そのものは伝えない）。

### 3. テスト送信（Claude または中島さん）
```powershell
& C:\work\anaconda_install\python.exe -I batch\notify_test.py --url-file "C:\Users\612316\Box\【個人】612316_中島　麻耶\keys\teams_webhook_test.txt"
```
- 「送信しました（HTTP 202）」などと表示され、Teams に「【KPI-PDCA通知】テスト送信」が届けば成功です。
- 送らずに中身だけ確かめるときは `--dry-run` を付けます。

### チャネルへ切り替えるとき（本番）
- 同じ「ワークフロー」で **「Webhook 要求を受信したらチャネルに投稿する」** テンプレートを使い、投稿先のチームとチャネルを選んで URL を発行し、同じように Box のファイルに保存して使います。

## 通知の方針（2026-11-25 決定）

- **Power Automate は使いません。** 通知は、Teams の「ワークフロー」（Webhook を受け取ったらチャネル／チャットに投稿）へ、毎営業日のバッチ（中島さんPC）が Adaptive Card を POST する方式です。
- バックアップ・停滞の検知・通知は、すべて、このバッチで行います（`docs/共通引継ぎプロンプト_PDCA仕組み化.md` 6章）。
- 通知先：
  - テスト：中島さんの個人チャット（作成済み。URL は `keys\teams_webhook_test.txt`。HTTP 202 を確認済み）。
  - 本番：事業ごとのチャネル（UN／SCH／MED／IS｜戦略Div）。チャネルごとに、同じテンプレートのワークフローを作り、URL を `keys\` に保管する。
- 担当者への個別の通知は、チャネルへの投稿の中で、担当を **@メンション**する形を想定（**要試験**。Adaptive Card のメンションが、ワークフローの投稿で効くかを確かめる）。個人ごとに別のワークフローを作る方法は、人数が多いので避ける。
- アプリの「通知設定」（宛先マスタ・担当対応表・チャネルマスタ・休日・ON/OFF）は、バッチが読む設定として使う（保存(JSON)の内容を読む）。
- 未実装：停滞の検知（共通資料 5-4）、通知の本番バッチ、チャネル用ワークフロー。
