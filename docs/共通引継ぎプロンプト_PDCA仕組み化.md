## 1. 目的と背景

- 目的：マーケティング運営のPDCAを**回りやすい仕組み・体制**にする（仕組み化・通知・管理表の使いやすさ）。
- 課題：施策の入力はあるのにPDCA（Check・Act）が止まる。実績が入らない、検証日が空、完了で止まり継続すべき施策が仕分けされていない。
- 使う素材：ROI／DSP／GEO／PDCA の各ダッシュボード、各事業の実績4ファイル（UN/SCH/MED/IS｜実績.xlsm）、本数管理、施策管理表、月次レポート。連携先は Teams・Outlook・Backlog。
- 環境条件：利用者側は**ブラウザでURLを開くだけ（インストール不要）**。サーバーは**DX課の社内サーバー**を使う（担当はDX課の上長。社内ツールとの連携は可能）。

### 3-2. 新しい提案（中島さんの承認待ち）

> 前回の「Excel入力のみ」を前提にした提案のうち、ダッシュボード入力への変更で成り立たなくなったもの（採否台帳の別Excel、Excelへの書き込み処理など）を、次の提案に置き換えます。**承認前は設計メモの扱い**で、実装は始めません。

| 番号 | 提案 | 内容 |
|---|---|---|
| A | **保存先は社内サーバーのデータベース＋Web画面** | 利用者はURLを開くだけ（インストール不要）。複数人が同時に入力でき、いつ・誰が・何を変えたかが自動で残る。バッチ処理も同じ保存先を読み書きするので、Excelのロック問題がなくなる |
| B | **採否台帳を別ファイルにしない（施策の表に統合）** | 提案（候補）も施策と同じ表に入れ、**「状態」で区別**する（候補／採用→未着手…／非採用）。非採用も消さずに残す。画面は「採否待ち」タブで候補だけ見る。ファイルが増えない |
| C | **段階移行（今のExcel運用を止めずに乗り換える）** | ①Excelを取り込んでWeb画面に初期データを作る（Excelはそのまま）→ ②本部だけで試す（同じアプリを中島さんのPCで動かす。社内からのアクセスが許可される場合）→ ③同じアプリをDX課サーバーへ引っ越し → ④全事業を切り替え、Excelは**読み取り専用の保管用**にする。切り替え日は中島さんが決める |
| D | **「Excelで出す」ボタン** | いつでも今の施策管理表と同じ形でExcelに書き出せる（バックアップ・二次利用・万一の巻き戻し用）。入力はWeb画面だけ |
| E | **受け入れ基準＝Excel操作チェックリスト** | 4章の「入力シートの要件」の操作が、実際の施策管理表のデータで普段どおりできることを、**本部の利用者2〜3名に試してもらって合格**したら次へ進む |

サーバーが使えない場合の代替（案）：SharePointリスト＋Power Apps等。ただし「ダッシュボードにしたい」という希望からは外れるため、**第一候補はA**。

## 4. 全体アーキテクチャ（rev.2）

```
ROI / DSP / GEO の出力 ──▶ ①気づきを機械が判定（要約ファイル signals）
                             │ 毎営業日のバッチ（AIなし。当面は中島さんPC、将来はDX課サーバー）
                             ▼
              ②施策の表に「候補」行を追加（状態＝候補） ◀── 手動追加（人）／AI示唆（中島さんが実行）
                             │ 定例で人が行をクリックし「採用／非採用／保留」を選ぶ（理由つき）
                             ▼
              ③採用 → 状態が「未着手」になり、同じ表の行として編集（人）
                             │ Backlogの「公開確認」完了日 → 検証日を自動設定
                             ▼
              ④検証値を右端の自動列に記入 → ⑤人が判定・次の一手
                             │ 継続なら次サイクル候補を自動起票
                             ▼
        同じWeb画面で入力・俯瞰・分析（入力シート／今週やること／パイプライン／効果分析）／Teams・Outlook通知
```

**画面の構成（案）**：入力シート（Excel風。UN／SCH／MED／ISのタブ）＋「採否待ち」「今週やること」「施策パイプライン」「効果分析」「負荷」。既存の KPI・PDCA管理アプリのKPI画面は当面そのまま残す。

実際の施策管理表の使い方を再現する。**◎＝必須、○＝あると望ましい**。

| 区分 | 要件 |
|---|---|

## 5. 共通データ仕様（ドラフト v0.2）

### 5-1. 要約ファイル signals（各ダッシュボードが出力）
```jsonc
{
  "schemaVersion": "0.1",
  "generatedAt": "2026-11-24T02:00:00+09:00",
  "source": "GEO",                  // GEO | ROI | DSP
  "signals": [{
    "id": "GEO-UN-業者推薦型-2026-11",   // 出所＋事業＋種類＋キーから決まる固定ID（毎日同じ気づきに同じID）
    "biz": "UN",                    // UN | SCH | MED | IS | ALL
    "kind": "低出現領域",
    "severity": "高",               // 高 | 中 | 低
    "summary": "UN・業者推薦型でAI出現率0%（8/8件で非出現）",
    "evidence": {"metric": "出現率", "value": 0.0, "target": null, "period": "2026-11-04", "n": 8},
    "destination": "施策",           // 施策 | 営業連携 | 運用タスク
    "suggestedActionType": "コンテンツ制作",
    "suggestedAction": "会社比較・選定ガイドページの整備（実績数・対応業種・ロットを明示）",
    "targetUrl": null,
    "link": "analysis.html"
  }]
}
```
- 判定ルールの例（**しきい値は仮**・運用で調整）：ROI＝MQL達成率が3か月連続で80%未満／段階別転換率が前年同月から大きく低下。DSP(GA4/GSC)＝検索経由セッションが前月比▲20%、AI経由が3か月連続増、表示回数が多くクリック率が低いページ。GEO＝優先度「高」かつ出現率0%の領域（既存のactionsをそのまま使う）。
- `destination` が「営業連携」（例：DSPの配信×来訪企業）は**施策の表に入れず**、件数だけ週次サマリーに載せる。

### 5-2. 候補（提案）の項目 ※旧「採否台帳」は廃止し、施策の表に統合（提案B・承認待ち）
候補は施策と同じ表の1行。状態が「候補」の間は、入力シートの標準表示には出さず、「採否待ち」タブに出す。

| 区分 | 項目 |
|---|---|
| 提案側（機械／手動追加は人） | 候補ID／提案日／出所（ROI・DSP・GEO・AI分析・AI次の一手・手動）／事業／種類（新規・次サイクル）／親施策No（次サイクルのみ）／提案内容／根拠／推奨担当／推奨検証日／推奨検証指標 |
| 採否側（人のみ） | 採否（採用・非採用・保留）／理由／決定日／決定者／メモ（採用後は施策Noが付き、状態が「未着手」になる） |
- 非採用の行は**消さずに残す**（記録）。非採用の候補は一定期間（仮：90日）は再提案しない（根拠が悪化した場合を除く）。
- 採用時は、行をクリックして内容を編集できる。
- 画面では「採否」の操作は行クリックの詳細パネルにボタンで置く（理由の入力を必須にする）。

### 5-3. 施策の右端に追加する項目（既存列の間には入れない）
起票元ID／施策タイプ（単発完了・継続改善）／対象URL／検証指標の種類／着手時値（自動）／検証値（自動）／取得日（自動）／判定（達成・未達）／次の一手／サイクル数／親施策No
- 「（自動）」は機械のみ、その他は人が記入。
- 画面では既存列の右端に並べ、詳細パネルでは「PDCA」欄としてまとめて表示する。
- **実際の追加は中島さんの確認後**（複製したデータで先に試す）。

### 5-4. 停滞の種類と検知（毎営業日）
1 採否待ち／2 検証日が空／3 実績が空（検証日超過）／4 判定・次の一手が空／5 継続改善型なのに次サイクルなし
- 通知：担当本人 → 同じ停滞が**2週続く**と上長以外の事業メンバー全員 → **3週**で定例の議題。通知先（担当→人物）は事業ごとに異なる。まず本部で試す。

### 5-5. 保存・書き込みの安全ルール（Excel書き込みから置き換え）
- 機械が書くのは「追加する候補行」と「右端の（自動）列」だけ。既存の人の入力は書き換えない。
- 保存先の変更はすべて**変更履歴**に残す（誰が・いつ・どの項目を・前の値→後の値）。誤入力から巻き戻せる。
- **日付つきバックアップ**を毎日作る（保存先はBox。世代・保持期間は旧設計の「日次30日＋月初」を踏襲）。
- 同じ行の同時編集は、後から保存した人に警告して上書きを防ぐ。
- 本番切り替えの前に、必ず**複製したデータ**で動作を確認する（提案C）。バッチの実行ログを残す。
- 移行時は、既存Excelを**取り込む前に日付つきでコピー**して残す。取り込み結果は件数（事業別の施策数）が元のExcelと一致することを確認する。
