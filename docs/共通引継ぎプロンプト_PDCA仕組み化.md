## 4. 全体アーキテクチャ（rev.3）

```
ROI / DSP / GEO の出力 ──▶ ①気づきを機械が判定（要約ファイル signals）
                             │ 毎営業日のバッチ（AIなし。中島さんPCで処理し、結果は Box に書く）
                             ▼
              ②Excel風シートに「候補」行を追加（状態＝候補） ◀── 手動追加（人）／AI示唆（中島さんが実行）
                             │ 定例で人が行をクリックし「採用／非採用／保留」を選ぶ（理由つき）
                             ▼
              ③採用 → 状態が「未着手」になり、同じシートの行として編集（人）
                             │ Backlogの「公開確認」完了日 → 検証日を自動設定
                             ▼
              ④検証値を右端の自動列に記入 → ⑤人が判定・次の一手
                             │ 継続なら次サイクル候補を自動起票
                             ▼
   Box の PDCAダッシュボードで入力・俯瞰・分析（既存のサマリー／PDCAボード等はそのまま）／Teams・Outlook通知
```

**画面の改修方針（案）**：既存の「📋 施策管理」タブに、**Excel風の「シート」表示**（UN／SCH／MED／ISの切替）を追加し、入力の標準画面にする。既存の一覧・カード表示、全体サマリー・施策別KPI・KPIツリー・PDCAボード（カンバン）・データ管理は残す。「採否待ち」は施策管理タブ内の切替で見せる。追加の俯瞰画面（今週やること・パイプライン等）は後の段階。

## 5. 共通データ仕様（ドラフト v0.3）

### 5-1. 要約ファイル signals（各ダッシュボードが出力）
```jsonc
{
  "schemaVersion": "0.1",
  "generatedAt": "2026-11-24T02:00:00+09:00",
  "source": "GEO",                  // GEO | ROI | DSP
  "signals": [{
    "id": "GEO-UN-業者推薦型-2026-11",   // 出所＋事業＋種類＋キーから決まる固定ID（毎日同じ気づきに同じID）
    "biz": "UN",                    // UN | SCH | MED | IS | ALL
    "kind": "低出現領域",
    "severity": "高",               // 高 | 中 | 低
    "summary": "UN・業者推薦型でAI出現率0%（8/8件で非出現）",
    "evidence": {"metric": "出現率", "value": 0.0, "target": null, "period": "2026-11-04", "n": 8},
    "destination": "施策",           // 施策 | 営業連携 | 運用タスク
    "suggestedActionType": "コンテンツ制作",
    "suggestedAction": "会社比較・選定ガイドページの整備（実績数・対応業種・ロットを明示）",
    "targetUrl": null,
    "link": "analysis.html"
  }]
}
```
- 判定ルールの例（**しきい値は仮**・運用で調整）：ROI＝MQL達成率が3か月連続で80%未満／段階別転換率が前年同月から大きく低下。DSP(GA4/GSC)＝検索経由セッションが前月比▲20%、AI経由が3か月連続増、表示回数が多くクリック率が低いページ。GEO＝優先度「高」かつ出現率0%の領域（既存のactionsをそのまま使う）。
- `destination` が「営業連携」（例：DSPの配信×来訪企業）は**シートに入れず**、件数だけ週次サマリーに載せる。

### 5-2. 候補（提案）の項目 ※採否台帳は廃止し、Excel風シートに統合（提案B・採用）
候補はシートの1行。状態が「候補」の間は、シートの標準表示には出さず、「採否待ち」の切替で見せる。

| 区分 | 項目 |
|---|---|
| 提案側（機械／手動追加は人） | 候補ID／提案日／出所（ROI・DSP・GEO・AI分析・AI次の一手・手動）／事業／種類（新規・次サイクル）／親施策No（次サイクルのみ）／提案内容／根拠／推奨担当／推奨検証日／推奨検証指標 |
| 採否側（人のみ） | 採否（採用・非採用・保留）／理由／決定日／決定者／メモ（採用後は施策Noが付き、状態が「未着手」になる） |
- 非採用の行は**消さずに残す**（記録）。非採用の候補は一定期間（仮：90日）は再提案しない（根拠が悪化した場合を除く）。
- 採用時は、行をクリックして内容を編集できる。採否の操作は詳細パネルのボタンで行い、理由の入力を必須にする。

### 5-3. 施策の右端に追加する項目（既存列の間には入れない）

### 5-6. Box で全員が同時に入力するしくみ（2026-11-24 承認）
今のアプリは「1つのJSONファイルを丸ごと上書き保存」するため、2人が近い時間に保存すると、片方の入力が消える（またはBoxに「競合コピー」ができる）。そこで次の形にする。**原則：1つのファイルに書く人は必ず1人だけ**。

```
生成AI\KPI-PDCA\
  KPI-PDCA管理アプリ.html              … 画面（全員が開く）
  data\kpi_pdca_data.json              … まとめたデータ（台帳の本体）← バッチだけが書く
  data\changes\<利用者>\<日付>.jsonl   … 各自の変更記録 ← 本人の画面だけが書く（日付ごとに別ファイル）
  data\changes\_済\…                   … まとめ終わった変更記録の保管（履歴）← バッチだけが書く
  backup\…                             … 毎日のバックアップ ← バッチだけが書く
```

- **入力したとき（自動保存）**：セルを確定するたびに、自分の今日の変更記録ファイルへ「いつ・誰が・どの施策の・どの項目を・前の値→後の値」を1行追記する。保存ボタンはない。
- **表示するとき**：「まとめたデータ」に全員の変更記録を**時刻の順に重ねて**表示する。開いたとき・一定間隔（例：1分ごと）で読み直し、他の人の入力を反映する。
- **同じセルを2人が変えたとき**：新しい方を表示し、もう一方も記録に残す。セルに印を付け、クリックで両方の値を見比べて選び直せる。
- **毎営業日のバッチ（中島さんPC）**：①バックアップ ②**前日までの**変更記録を「まとめたデータ」に書き込む（どこまで取り込んだかを本体に記録）③取り込んだ変更記録を `_済` へ移す。**今日のファイルには触らない**ので、入力中の人とバッチがぶつからない。
- **バッチが止まっても消えない**：変更記録がたまるだけで、画面は正しく表示される（開くのが少し遅くなる）。次のバッチでまとめて片付ける。
- 制約：①Boxの同期が終わるまで（数秒〜数分）他の人の入力は見えない ②**Box Drive（PCの中でBoxをフォルダとして見せるソフト）とChrome/Edgeが必要**（フォルダへの書き込みは、初回だけ「フォルダを選んで許可」の操作が要る）③Boxのブラウザ画面（プレビュー）ではアプリは動かない。
- 利用者名：初回に宛先マスタから自分の名前を選び、ブラウザに記憶する（変更履歴・決定者に使う）。
