# 施策管理表アプリ化 設計提案書（二重管理の解消）

## 0. この文書の位置づけ

「施策管理表（Excel）」と「KPI・PDCA管理アプリ」の**二重管理をやめ、施策管理表の全機能をアプリ側に取り込んで、PDCA・KPI管理と一体で使えるようにできるか**というご質問への回答と、実現方針の提案です。実装はまだ行っていません。方針をご承認いただいてから着手します。

**結論：可能です。** 施策管理表（UN/SCH/MED/IS各シート・A〜]列・最大4組のKPI/目標/実績）を、アプリ内で新規追加・編集・削除でき、既存Excelとの相互変換（取込＋同一レイアウトへの書き戻し）と、PDCA・KPIとの双方向連携を備えた「唯一の管理元」にできます。

## 1. 現状の課題（なぜ二重管理になっているか）

現在のアプリは施策データを **「取り込んで表示する」だけ** で、施策そのものの追加・編集・削除はアプリ内でできません。そのため、施策の更新は必ず元Excel（`施策管理表.xlsx`）側で行い、アプリはそれを再取込する運用になっています。結果として、

- 施策の起票・更新は Excel、進捗の可視化は アプリ、という**二拠点管理**になる
- アプリ内で作った新規施策（`newShisaku`）やPDCAの結果が、Excel側へ反映されない（引継ぎドキュメントのTODO 2・3）
- 施策管理表は**列の一部しか取り込んでいない**（下表）ため、アプリで見える情報が元表より少ない

### 現在アプリが取り込んでいる列（施策管理表 → `shisaku`）

| 取込済み | 列 | 項目 |
|---|---|---|
| ✅ | A | No |
| ✅ | B | 大分類 |

## 2. 提案する全体像

アプリに **「施策管理」タブ** を新設し、施策管理表と同等以上の管理をアプリ内で完結させます。データの流れは次のとおりです。

```
                ┌───────────────────────────────────────────┐
   既存Excel ──▶│  アプリ（唯一の管理元）                       │──▶ Excel書き戻し
 施策管理表.xlsx │  ・施策管理タブ（全列CRUD／4組KPI／プルダウン） │  同一レイアウトの
 （初回取込のみ）│  ・PDCAボード（施策と双方向リンク）            │  施策管理表.xlsx を出力
                │  ・KPI（本数・ツリー・ファネルへ連携）          │  （BOX共有・バックアップ）
                └───────────────────────────────────────────┘
                          ▲                       │
                          └──── JSON保存/取込 ─────┘（日々の保存はJSON）
```

- **初回**：既存 `施策管理表.xlsx` を全列取込 → 以後はアプリが正となる
- **日常**：アプリ内で施策を起票・更新（Excelは開かない）。保存はJSON（現行どおりBOX共有）
- **共有・配布時**：必要に応じて「施策管理表と同じ列構成のxlsx」を書き出し、従来のExcelを差し替え（＝二重管理の解消）

## 3. 画面設計（施策管理タブ）

### 3-1. 一覧ビュー
- 事業（全社/UN/SCH/MED/IS）と期間の絞り込みは既存の共通フィルタを流用
- 施策を表形式で一覧（No／大分類／施策種類／施策内容／担当／ステータス／公開日／検証日／KPI①達成状況）
- ステータス（未着手・進行中・完了 等）で色分け、テキスト検索・大分類/種類/担当のフィルタ
- 行の操作：**編集／複製／削除／PDCA案を作成**、ヘッダに **＋新規施策**
- アプリ内新規施策（`newShisaku`）と取込施策（`shisaku`）を統合表示（出所バッジで区別）

### 3-2. 施策編集モーダル（全列対応）
- 基本情報：No（自動採番可）・大分類・課題目的・手法・施策種類・施策内容・担当・関連施策No・コラム/メルマガ/WP No・事例会社・backlog・優先順位
- 日付：着手日・公開/配信/実施日・検証日
- ステータス：プルダウン（リストシート由来）
- **KPIセット（最大4組）**：KPI名／目標／実績を1組目〜4組目まで。「＋KPIを追加」で可変
- 各項目はリストシートのマスタからプルダウン選択（自由入力も可）

### 3-3. PDCA・KPIとの連携（画面上の導線）
- 施策編集画面から「この施策のPDCA案を作成」→ PDCA案モーダルへ（施策No・カテゴリ・現状値を自動転記）
- PDCAで記録した「次サイクルの目標値」を、施策の**2組目以降のKPIセット（V/W/X…）へ書き戻し**（引継ぎTODO 3の実現）
- PDCAの結果・実績を、施策の実績列（U）へ自動反映（引継ぎTODO 1の実現）

現行の `shisaku`（dict[biz][] ）を、全列を保持する形に拡張します（後方互換：既存フィールドは維持）。

## 5. Excel 双方向（二重管理を解消する要）

### 5-1. 取込（Excel → アプリ）
- 現行の取込ロジックを全列対応に拡張（A〜]、4組KPI、着手日・関連施策・コンテンツNo・事例会社・backlog・優先順位）
- 「リスト」シートをマスタとして取込
- 取込結果を必ず件数表示（無言成功を作らない：反映不具合の再発防止と同方針）

### 5-2. 書き戻し（アプリ → Excel）
- アプリの `shisaku`（＋アプリ起票分）を、**元の施策管理表と同じ列レイアウト（A〜]、4組KPI）** の `.xlsx` として出力
- 事業ごとにシート（UN/SCH/MED/IS）を再現。ヘッダ行・P/A/D/C のバンド行も再現
- これにより「アプリで管理 → 必要時にExcelを再生成してBOX共有」が回り、Excelを直接編集する運用を廃止できます

> ⚠️ 制約：ブラウザからは元xlsxの**セル数式・条件付き書式・入力規則（プルダウン）・シート保護**をそのまま保持できません。書き戻しは「値」ベースの再生成です（レイアウト・値は再現、Excel側の仕掛けは再現されない）。プルダウンの整合性はアプリ内マスタで担保します。

## 6. 二重管理の解消後の運用フロー（案）

1. 施策の起票・更新は **アプリの施策管理タブ** で行う（Excelは開かない）
2. 進捗・成果は同じアプリのKPI／PDCAでそのまま可視化
3. 保存は現行どおり **JSON保存 → BOX共有**（アプリ間の受け渡し）
4. 経営会議・他部署共有など**Excelが必要な時だけ**「施策管理表xlsxを書き出し」で最新版を生成

---

## 7. 制約・リスク（先に共有すべき点）

1. **単一HTML・ローカル完結**のため、複数人が同時に同じデータを編集することはできません（1人ずつ編集し、JSON/xlsxで同期）。厳密な同時共同編集が必要なら、将来的にクラウドDB化が別途必要です。
2. **Excelの数式・書式・入力規則は書き戻しで再現されません**（値とレイアウトのみ）。「Excelマクロ・関数を残したい」要件がある場合は要相談。
3. ファイルサイズが増えます（現状約460KB → 施策全列＋UIで増加）。動作速度への影響は軽微の見込みですが、実装時に検証します。
4. 既存データとの互換：拡張は後方互換で行い、旧JSONもそのまま読めるようにします。

## 8. 実装フェーズ案（段階的に価値を出す）

| フェーズ | 内容 | 主な成果 |
|---|---|---|
| **F1** 全列取込＋一覧表示 | 施策管理表の全列（4組KPI・リストマスタ含む）を取込み、施策管理タブで一覧・検索・フィルタ表示 | まず「元表の情報が全部アプリで見える」状態に。二重"閲覧"を解消 |
| **F2** アプリ内CRUD | 新規・編集・複製・削除、`newShisaku`統合、プルダウン入力 | 施策の更新をアプリで完結。Excel編集を廃止 |
| **F3** Excel書き戻し | 同一レイアウトのxlsx出力（事業別シート） | BOX共有用Excelをアプリから生成。二重"管理"を解消 |
| **F4** PDCA/KPI双方向連携 | 施策実績→PDCA元結果の自動転記（TODO1）、PDCA目標→施策KPI②以降へ書き戻し（TODO3） | 施策・PDCA・KPIが一体で回る |

各フェーズはこれまでどおり作業ブランチで実装 → マージ前レビュー（構文チェック＋jsdom検証の結果提示）→ 承認後に main へマージ、の流れで進めます。
