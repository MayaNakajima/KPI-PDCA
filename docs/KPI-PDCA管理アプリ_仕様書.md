## 1. 概要

マーケティング本部の「KPI管理」「PDCA運用」「施策管理」を1つのツールで完結させる、ブラウザで開くだけで動作する単一HTMLアプリです。サーバー・インストール不要で、`KPI-PDCA管理アプリ.html` をダブルクリックして開くだけで使用できます。

- **対象事業**：UN（企業ユニフォーム）／SCH（スクール・学生服）／MED（メディカルウェア）／IS（インサイトセールス）／SC（スペースクリエイト・準備中）
- **対象会計年度**：2026年度（2026年3月〜2027年2月）
- **データの保存方式**：ブラウザを閉じても直前の編集内容はブラウザのローカル保存（下書き）に残りますが、正式な保存・共有は「JSON保存」でファイルを書き出し、BOX等の共有場所を更新する運用です。

## 2. 全体構成（画面タブ）

画面上部のタブで以下を切り替えます。

| タブ | 内容 |
|---|---|
| 📊 全体サマリー | ファネルKPI（セッション→MQL→SAL→SQL→受注）の目標・実績・達成率、CV流入元、月次推移、配分ギャップ・パネル |
| 🎯 施策別KPI | カテゴリ別（コラム・メルマガ・WP等）の実施本数目標/実績、成果CV寄与。**「表示カード設定（事業部別）」で、事業部ごとに表示する施策種類カードを選択可**（下記） |
| 📋 施策管理 | 施策の一覧・詳細・新規作成・編集・削除、Excel（施策管理表）との相互取込・書き出し |
| 🌳 KPIツリー | チャネル別／ページ別セッション目標と実績 |
| 🔁 PDCAボード | Plan→Do→Check→Actの改善サイクル管理、要仕分け／実績未記入アラート |
| 🗂️ データ管理 | 実績・目標の直接入力、Excel/JSON入出力 |

画面共通で、上部の事業タブ（全社/UN/SCH/MED/IS/SC）と対象期間（開始月〜終了月）で絞り込みができます。

ヘッダー右上のボタン：

- **📥 取込**：施策管理表／本数管理／実績ファイル／データ(JSON) の取込モーダルを開く
- **💾 保存(JSON)**：現在のデータをJSONファイルとしてダウンロード（正式な保存）。バックアップ設定済みなら同時に自動バックアップも実行
- **🗄 バックアップ設定 / 🔔 通知設定**：バックアップ先・世代、通知の宛先マスタ・チャネル・休日カレンダー・ON/OFF・通知テスト（5・6章参照）
- **⬇ Excel出力**：期間・事業・内容を指定してExcelファイルへ出力

### 施策別KPIタブ：事業部別の表示カード設定

施策別KPIタブの「🃏 表示カード設定（事業部別）」ボタンから、**事業部（UN/SCH/MED/IS）ごとに表示する施策種類カードをチェックで選択**できます（外すと非表示）。設定は**アプリのデータに保存され、JSON共有で全員共通**になります。事業タブを「全社」にしている場合は全カードを表示し、個別事業を選ぶとその事業部の設定が適用されます。

## 3. 📋 施策管理タブ

施策管理表（Excel）とアプリの二重管理を解消するために追加したタブです。Excelを主に使う人・アプリを主に使う人のどちらでも運用できる「同期モデル」を採用しています。

### 3-1. 一覧表示

- **検索**：No・施策内容・担当・手法などを横断的にテキスト検索
- **絞り込み（複数選択可）**：大分類／施策種類／状態／担当の4つ。ボタンをクリックするとチェックボックスのパネルが開き、複数の値を同時に選択できます（例：種類＝「コラム」と「メルマガ」を同時に選んで絞り込み）。選択件数はボタンのラベルに表示されます（例：種類(2)）
- **列の表示切替**：表示する列をチェックボックスでON/OFF。**初期状態は全列を表示**します（必要に応じて隠せます）。
- **複数列ソート**：列見出しをクリックで並び替え、Shiftキーを押しながら別の列見出しをクリックすると第2キー・第3キーとして追加されます（見出しに▲1▲2のように優先順位が表示されます）。**ソートの指定は各自のブラウザに保存**され、次回開いたときも保持されます（保存は利用者のPC／ブラウザ単位。共有サーバー上での個人別ビューではありません）。
- **表示密度・列幅**：1行の高さを抑えて**一度に多くの行**を表示します。列幅は見出しの文字数で固定せず内容に合わせ、必要な場合は**横スクロール**で対応します。**「操作」列のボタンは文字が縦書きにならず1行**で表示されます。
- **削除候補を表示**：チェックを入れると、削除された（＝削除候補フラグが立った）施策のみを表示し、復元または完全削除ができます

### 3-2. 一覧／カード表示の切替

- **📋 一覧**：表形式。行の「詳細」「編集」「複製」「削除」ボタンから各操作が可能
- **🗂 カード**：1施策＝1カードで表示（横長になりがちな施策管理表の閲覧性を改善）。カード下部に同じ操作ボタンあり

### 3-3. 施策の新規作成・編集・複製・削除

- **＋新規施策**ボタンから新規作成。No.は「事業コード＋連番」で自動採番されます（例：`MED-001`）。既存の最大番号を確認して重複しないよう採番します
- 編集モーダルでは以下を入力できます：大分類／課題・目的／関連施策No／手法／施策種類／施策内容／担当／事例会社／コラム・メルマガ・WP No／backlog URL／優先順位／状態／施策タイプ（単発完了型／継続改善型）／着手日／公開・配信・実施日／検証日／KPIセット（KPI名・目標・実績を最大4組まで、＋KPIを追加ボタンで追加可能）
- 主要項目（大分類・手法・種類・優先順位・状態・KPI）は、施策管理表の「リスト」シート由来のマスタからオートコンプリート候補が出ます（自由入力も可能）
- **複製**：既存施策の内容をコピーして新規No.で登録（内容末尾に「（複製）」を付記）
- **削除**：即座には消えず「削除候補」フラグが立ちます。「削除候補を表示」から復元、または完全削除が可能です（誤削除防止）

### 3-4. Excel（施策管理表.xlsx）との相互取込・書き出し

**取込（Excel→アプリ）**：ヘッダーの「📥 取込」→「施策管理表」から `施策管理表.xlsx` を選択すると、UN/SCH/MED/IS各シートの全列（KPI・目標・実績は最大4組。事業ごとに列数が異なっても自動検出）と「リスト」シート（マスタ）を取り込みます。

このとき、施策No.を単位に**1件ずつ**次のルールで自動マージされます（全置換はしません）：

| 状況 | 動作 |
|---|---|
| Excelにのみ存在する施策No. | 新規追加 |
| 内容が完全に一致 | 何もしない |
| アプリ側で編集済み（新規作成／編集）かつExcel側の内容も変わっている | **競合**として、競合解決モーダルで解決方法を選択（下記4択） |
| アプリ側は未編集でExcel側だけ変わっている | 自動的にExcel側の内容へ更新 |
| アプリのデータにあるがExcelから消えている（かつアプリ発の施策ではない） | 即削除せず「削除候補」フラグを立てる |

**競合解決モーダル（4択）**：競合が発生すると取込直後にモーダルが開き、施策ごとに差分（項目・Excel側の値・アプリ側の値）を確認しながら、次から解決方法を選べます。

1. **Excel版を採用**（アプリ版は破棄）
2. **アプリ版を採用**（Excel版は破棄）
3. **項目ごとにマージ**：同じ施策で項目単位に食い違っている場合、項目ごとに残す側（Excel/アプリ）を選択し、両方の編集を活かします
4. **別々の施策として両方残す**：No.がたまたま重複しただけの別施策の場合、両方を残し、片方に新しい連番No.を自動採番します（既定は既存側のNo.を維持し、取込側へ新No.を採番）

**No.重複の予防**：Excelで新規行を追加するときは**No.を空欄**にしておくと、取込時にアプリが自動採番（No.空欄＝新規扱い）し、手採番によるNo.重複を根本的に減らせます。手採番で重複したぶんは上記4で救済します。

**書き出し（アプリ→Excel）**：ヘッダーの「⬇ Excel出力」で「施策一覧」を含めて出力すると、全列（関連No・事例会社・backlog・優先度・着手日・可変数のKPIセット）を含んだExcelファイルが生成されます。**backlogのURLは実際にクリック可能なハイパーリンクとして書き出されます。**

> ⚠️ **制約**：見出しセルの色（塗りつぶし）は、現在読み込んでいるExcelライブラリ（SheetJS Community版）では書き出しに対応していません（読み込みは可能）。対応するには有償版の導入、または独自にExcelファイル形式を組み立てる実装が別途必要です。また、Excelのプルダウン（データ入力規則）・条件付き書式・数式もそのままでは再現されません（値としては正しく書き出されます）。

### 3-5. マスタ（プルダウン候補）の管理

大分類・優先順位・手法・状態・施策種類・KPI項目のマスタは `施策管理表.xlsx` の「リスト」シートを初回の初期値として取り込みますが、以後はアプリ側の管理となります。施策の新規作成・編集時に入力した新しい値は自動的にマスタへ追加登録され、次回以降の入力候補として使えます（Excel「リスト」シート側の変更は自動では反映されません）。

### 3-6. 施策種類の一元化（全画面へ自動反映）

**施策種類のマスタを単一の正**とし、新しい施策種類を追加すると（施策編集・「リスト」取込・マスタ編集のいずれでも）、関連画面すべてに自動で反映されます。

- 施策管理タブ（絞り込み・入力候補）
- **施策別KPI（実施本数）**：新しい種類が実施本数の行として自動追加され、目標／実績もそこで管理できます
- PDCAボード（KPI選択肢「施策本数：〈種類〉」）
- Excelの取込・書き出し

種類の**改名は全画面へ伝播**し、**使用中の種類の削除は保護**（確認後のみ）します。なお **KPIツリー**タブは「チャネル／ページ別セッション」を扱う別軸のため、施策種類はここには現れません（設計どおり）。

## 4. 🔁 PDCAボード（施策管理タブ関連の追加機能）

- **要仕分けパネル**：検証日を過ぎているのに「施策タイプ」（単発完了型／継続改善型）が未設定の施策を自動的にリストアップします。「単発完了とする」ボタンでその場で仕分け完了、「継続してPDCAを回す」ボタンでPDCA案作成モーダルを自動的に開きます。
- **実績未記入パネル**：検証日を過ぎているのにKPIの実績値が未記入の施策を自動的にリストアップし、「実績を入力」ボタンから編集モーダルへ直接遷移できます。
- **PDCAモーダルの判定基準欄**：改善案（Act）の達成/未達を判断する基準を明文化して記録できます（例：「CVR 0.5%以上で達成」）。

## 5. 🗄 バックアップ（更新時＋週次＋月次）

バックアップ先は**Box（自動で世代バックアップ）**です。3系統で構成します。

| 系統 | 契機／スケジュール | 保持世代 | 実行場所 |
|---|---|---|---|
| **更新時** | 「保存(JSON)」を押すたび | 短期プールに追加（**30世代**） | アプリ内（実装済み） |
| **週次** | **毎週月曜 9:30**（月曜が休日なら翌営業日） | 短期プールに合流（更新時と共有・30世代） | クラウド自動化 |
| **月次** | **毎月1日 9:30**（1日が非営業日なら、その月の最初の営業日に1回だけ） | **13世代**（約1年分） | クラウド自動化 |

- **更新時バックアップ（実装済み）**：ヘッダー「🗄 バックアップ設定」でBox同期フォルダを指定すると、「保存(JSON)」のたびに日時付きスナップショット（`kpi_pdca_backup_YYYY-MM-DD_HHMMSS.json`）を書き出します。一度指定すればブラウザに記憶されます。対応ブラウザはChrome／Edge等（File System Access API対応）。非対応ブラウザ（Firefox／Safari等）ではダウンロードにフォールバックします。
- **世代管理**：短期プール（更新時＋週次）は最新30世代、月次プールは最新13世代を保持し、超過分を古い順に自動削除します。
- **営業日ロジック**：休日＝土日＋日本の祝日（自動判定）＋会社独自の休業日（アプリに登録）。週次は月曜が休日なら翌営業日に、月次は1日が非営業日なら月初の最初の営業日に1回だけ実行します（当月重複実行なし）。

**保存先（Box）フォルダ構成**：`…/Box/マーケティンググループ/マーケティング戦略Div/施策管理表｜PDCA管理/` 配下に次の構成で保存します。**アプリ本体（HTML）もこのフォルダに置き**、全員がBoxから同じアプリを開く運用にします。

```
…/施策管理表｜PDCA管理/
├─ KPI-PDCA管理アプリ.html   ← アプリ本体（Boxから開く）
├─ data/                      ← 最新の正データJSON（ここを更新する運用）
└─ backup/
   ├─ rolling/                ← 更新時＋週次月曜（最新30世代）
   └─ monthly/                ← 月初営業日（最新13世代）
```

更新時バックアップ（アプリ内）も保存先を `backup/rolling/`（Box同期フォルダ）に向ければ、アプリ発とクラウド発が同じ場所に集約されます。各ファイル名は `kpi_pdca_backup_YYYY-MM-DD_HHMMSS.json`。

> ⚠️ **前提**：週次・月次の自動実行は、アプリを開いていない・PC電源オフでも動くよう、**クラウド側の仕組み（推奨：Power Automate＋Boxコネクタ）が必要**です。更新時バックアップのみアプリ内で完結します。
> ℹ️ **要確認**：週次バックアップは短期(30)プールに合流する前提です（世代数の指定が更新30／月次13の2つのため）。独立管理が必要なら別途世代数を指定してください。

## 6. 🔔 通知（Teams）

対応が必要な施策を、Teamsの**Adaptive Card**（見出し＋対象施策の一覧＋各施策のリンク付き）でリマインドします。2種類。

| 種類 | 頻度 | 宛先 |
|---|---|---|
| **A：毎朝ダイジェスト** | 毎朝 9:00（営業日） | 担当者本人＋マネージャー（人単位・@メンション/DM） |
| **B：週次チームサマリー** | 月曜 10:00（休日なら翌営業日） | 事業チャネルへ全体投稿（チャネル単位） |

**通知トリガー（対象施策の抽出条件）**：(1) 検証日が近い（**2日前**）、(2) 公開後**2日**経っても実績が未記入、(3) 新規施策が着手日を過ぎても未着手。

**社外担当の振替**：担当者マスタに「社外フラグ」と「振替先（社内の人・人単位）」を持ちます。担当が社外の施策は、**本人には通知せず**、振替先（マネージャーまたは社内担当者）へのみ通知します。担当が社内の場合は本人＋マネージャーへ通知します。担当（施策の`tanto`）と宛先マスタは**対応表**で紐付け、表記ゆれがあっても確実に突合します（突合できない担当は「宛先未設定」として警告一覧に表示）。

**発信元の表示**：通知はPower Automateの**Flow bot として投稿**するため、送信者はTeams上で「**Workflows**」と表示され、**個人名（Mayaさん）は出ません**（フローの所有・接続は個人アカウント）。「Workflows」は固定名で任意名には変えられないため、**Adaptive Cardの冒頭に「【KPI-PDCA通知】…」等の見出し**を付けて、何の通知かが一目で分かるようにします。

**B通知の投稿先チャネル**（チーム「営業DX推進」）：UN｜戦略Div／SCH｜戦略Div／MED｜戦略Div／IS｜戦略Div。

**通知先の管理（アプリ内）**：
- 宛先マスタ（氏名／TeamsのUPN・メール／社外フラグ／マネージャー・振替先）、担当対応表、チャネルマスタ（事業→Teamsチャネル）を**アプリ内で編集**できます。
- **ON/OFF機能**：通知全体・種別（A/B）ごとに有効/無効を切替できます。
- **通知テスト機能**：運用開始前に、指定宛先へ実際にサンプル通知を送り、見た目・宛先・メンションを確認・調整できます。

> ⚠️ **前提**：個人単位とチャネル単位の宛先は併用できます。@メンション/DM/チャネル投稿・スケジュール送信は、クラウド側（**Power Automate、Mayaさん個人アカウント接続**）で行います。詳細な実装・設定手順は [`docs/実装指示プロンプト_バックアップ通知.md`](実装指示プロンプト_バックアップ通知.md) と [`docs/PowerAutomate_Box設定手順書.md`](PowerAutomate_Box設定手順書.md) を参照。

## 7. データの更新方法（運用フロー）

| データ | 取込元 | 取込方法 |
|---|---|---|
| ファネル実績（セッション/MQL/SAL/SQL） | ROIダッシュボードJSON | 取込→「データ(JSON)」。ROI形式は自動変換されます（目標(targets)は現状変換対象外） |
| 成果CV流入元 | 各事業の実績xlsm | 取込→「実績ファイル」（複数選択可） |
| 施策一覧 | 施策管理表.xlsx | 取込→「施策管理表」。No.単位で自動マージ（3-4節参照） |
| 実施本数 | 本数管理.xlsx | 取込→「本数管理」 |
| チャネル/ページ別セッション実績 | （手入力のみ） | 「データ管理」タブで直接入力 |

編集後は必ず「💾 保存(JSON)」でファイルを書き出し、共有先（BOX等）を更新してください。バックアップ設定をしている場合は同時に自動バックアップも作成されます。

## 8. 既知の制約

1. **単一HTML・ローカル完結**のため、複数人が同時に同じデータを編集することはできません（1人ずつ編集し、JSON/Excelで同期）。
2. **見出しセルの色のExcel書き戻しは非対応**（3-4節参照）。
3. **バックアップの週次/月次自動実行・Teams通知は、クラウド側の自動化（推奨：Power Automate＋Boxコネクタ）が前提**（5・6章参照）。仕様は確定済み、実装は [`docs/実装指示プロンプト_バックアップ通知.md`](実装指示プロンプト_バックアップ通知.md) に準拠。更新時バックアップのみアプリ内で完結。
4. Excelのプルダウン（入力規則）・条件付き書式・数式は書き戻しで再現されません（値は正しく再現されます）。
5. 施策管理の「競合判定」はExcel再取込時のみ動作し、アプリ単体の同時編集は検知対象外です。

## 9. 用語

- **施策No.**：施策を一意に識別する番号。Excel取込分は元の番号のまま、アプリ内で新規作成した施策は「事業コード-連番」（例：MED-001）で自動採番されます。
- **削除候補**：即座に削除せず、フラグを立てて一覧から除外している状態。復元・完全削除が可能です。
- **施策タイプ**：単発完了型（一度きりの実施で目標達成なら完了）／継続改善型（CVR改善など継続的にPDCAを回す施策）の区分。
- **競合**：Excel再取込時に、アプリ側でも編集済みかつExcel側も変更されていた施策のこと。
